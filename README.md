# Карта оптической сети

Программа для работы с оптической сетью — веб-сервис для визуализации и учёта волоконно-оптической и смежной инфраструктуры: ВОЛС (воздух и подземка через колодцы), узлы с коммутаторами, оптические кроссы и муфты, GPON (OLT, сплиттер, ONU), камеры и медиаконвертеры с медными линиями к коммутатору, Wi‑Fi радиомосты (P2P и P2MP) с радиолинками и зонами покрытия. Подложка — Яндекс.Карты (облако) или Leaflet + ортофото (on-prem). Одна карта на организацию: данные изолированы по компаниям, совместная работа через синхронизацию в реальном времени.

**Версия:** 1.2.0

**Работа в облаке:** [volsmap.ru](https://volsmap.ru/) — лендинг и вход; карта после авторизации. Установка ПО у заказчика не требуется.

**Portable (on-prem):** каталог [Portable/](Portable/README.md) — урезанная версия для выдачи на чужие сервера (без лендинга, регистрации, почты и платформенной админки). Инструкция для клиента: [Portable/INSTALL.md](Portable/INSTALL.md).

**Документация:** каталог [docs/](docs/README.md) — структура репозитория, разработка, frontend, backend, on-prem basemap; справочник модулей в [public/js/README.md](public/js/README.md). В приложении — кнопка «Справка» (`public/js/ui/help.js`).

Ниже — краткий обзор; подробные инструкции для разработчиков — в `docs/`.

## Возможности

- **Визуализация** — узлы (в т.ч. с коммутаторами), отдельные коммутаторы на карте, оптические кроссы, кабельные муфты, опоры связи, крепления, **колодцы**, кабели ВОЛС, объекты GPON (OLT, сплиттер, ONU), камеры, медиаконвертеры и Wi‑Fi радиомосты
- **Кросс и муфта** — рабочее место волокон: вкладки «Схема» и «Таблица», соединения, вывод на узлы/ONU/сплиттеры/медиаконвертер/радиомост; у кросса — учёт медных портов (RJ45); сплиттеры на схеме кросса
- **Подземные участки ВОЛС** — между соседними колодцами всегда подземный пунктир (вход → клики по карте → выход или колодец→колодец); перепрокладка из карточки колодца; воздух — после выхода на опору/крепление
- **Медные линии** — подключение камеры, медиаконвертера или радиомоста к порту коммутатора узла или отдельного коммутатора; учёт портов RJ45 и SFP
- **Wi‑Fi радиомосты** — режимы P2P (точка‑точка) и P2MP (базовая станция и абонентские станции); порт RJ45 или SFP; прямые радиолинии на карте; зона покрытия (круг или направленный луч)
- **Трассировка волокон** — путь оптического волокна от узла до узла через муфты и кроссы; от порта OLT (в т.ч. все пути при разветвлении через сплиттер); из карточки камеры — по волокнам кросса, подключённым к узлу коммутатора (или по входному волокну медиаконвертера); учёт подземных сегментов на трассе
- **Редактирование** — добавление и удаление объектов, прокладка кабелей ВОЛС и медных линий, соединение волокон в кроссах и муфтах, подключение волокон кросса к узлам сети
- **Кабели** — ВОЛС (число волокон и цвета в карточке; модульный ВОЛС с пресетами); опоры, крепления и колодцы как точки трассы; медные — от коммутатора к камере, медиаконвертеру, радиомосту и др.
- **Кросс** — соединение волокон между кабелями, вывод волокон на узлы сети (выбор волокна и кнопка «Подключить к узлу»)
- **Группы** — объединение нескольких кроссов или узлов в одной точке
- **Регионы и зоны** — регионы (логическое разделение карты) и зоны-полигоны; скрытие заливки или содержимого
- **Поиск** — по названию в шапке, центрирование на объекте
- **Отмена и повтор** — до 20 действий за сессию: **Ctrl+Z** (отменить), **Ctrl+Y** / **Ctrl+Shift+Z** (повторить); кнопки в шапке. Учитываются только ваши действия в текущей вкладке
- **Выделение областью** — зажмите правую кнопку мыши и потяните по карте; после отпускания панель со статистикой объектов и кнопка «Удалить выделенное» (в режиме редактирования)
- **Фильтр карты** — показ только выбранных типов (узлы, в т.ч. «только узлы агрегации», кроссы, муфты, опоры, крепление, колодцы, OLT, сплиттеры, ONU, камеры, медиаконвертеры, Wi‑Fi радиомосты); кабели отображаются только между видимыми объектами
- **GPON** — OLT (приход от кросса, PON-порты, назначение волокон), сплиттер (1:N, вход/выходы), ONU; подключение волокна к ONU и сплиттеру из кросса/муфты с прокладкой маршрута через опоры и крепления; выходы сплиттера на ONU/сплиттер с маршрутом; трассировка от порта OLT, в т.ч. все пути при сплиттере; экспорт/импорт полей GPON
- **Справочник устройств** — активное оборудование, оптика (типы муфт/кроссов/кассет), инфраструктура (ящики, кабели с палитрой волокон)
- **Экспорт / Импорт** — JSON карты организации; импорт проектов NeD (`.ned`) добавляется в центр текущего вида
- **Авторизация** — администратор организации (редактирование) и пользователь (просмотр); глобальный администратор — панель `/site-admin.html`
- **Защита входа** — лимит попыток с IP (`authRateLimit*`)
- **2FA для организации** — администратор организации включает общий TOTP-код (приложение-аутентификатор, например Яндекс.Ключ) для всех пользователей при входе
- **Организации и доступ** — отдельная карта, история и бэкапы на организацию; лимиты одновременных пользователей; личный кабинет с лимитами объектов на карте
- **Zabbix** — встраивание карты в дашборд; опциональный мониторинг хостов (кольцо статуса на объектах)
- **Чат команды** — переписка внутри организации (текст, файлы, @упоминания)
- **История изменений** — журнал действий с фильтрами по пользователю, типу действия и датам; бейдж непрочитанных в шапке
- **Типы узлов** — обычный / агрегации с разными цветами и отображением внутри группы узлов
- **Начальная позиция карты** — каждый пользователь может сохранить текущий вид как начальный
- **Мобильный просмотр** — на экранах шириной ≤768px доступен только режим просмотра; редактирование — с компьютера или планшета в альбомной ориентации с большей шириной
- **Интерфейс** — складывающаяся левая панель; светлая и тёмная тема; настройки производительности (LOD, виртуализация)
- **Синхронизация** — совместная работа в реальном времени (пооперационная), курсоры участников, блокировка объекта при редактировании карточки
- **Хранение** — режим `json` (`data/store.json`: организации, пользователи, `mapDataByOrg`, история, настройки, `pricingPlans`) или `mysql` (см. [docs/SERVER.md](docs/SERVER.md), [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md))
- **Резервные копии** — ежедневно для каждой организации в `data/backups/<id_организации>/backup-YYYY-MM-DD.json`; хранятся 30 дней; для MySQL — также `npm run backup:mysql`

## Быстрый старт (пользователи сервиса)

1. Откройте [volsmap.ru](https://volsmap.ru/) и нажмите **Начать бесплатно** или **Войти**
2. Зарегистрируйте организацию или войдите под выданными учётными данными
3. В приложении откройте блок **Синхронизация** → **Подключиться** — загрузится карта вашей организации
4. На широком экране включите **Редактирование** для добавления объектов и кабелей

Данные хранятся на серверах сервиса; отдельная установка у вас не нужна.

## Локальная разработка

```bash
npm install
cp server/config/server-config.example.json server-config.json
# Укажите yandexMapsApiKey в server-config.json
npm run api
```

| URL | Страница |
|-----|----------|
| http://localhost:3000 | Лендинг (`pricing.html`) |
| http://localhost:3000/index.html | Карта |
| http://localhost:3000/auth.html | Вход |

Далее: вход (часто `admin` / `admin123` при первом запуске) → **Синхронизация** → **Подключиться**.

Без запущенного API карта не работает. Без ключа Яндекс.Карт подложка не загрузится.

Подробнее: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Режимы и объекты

| Режим | Описание |
|-------|----------|
| **Просмотр** | Навигация, клик по объектам — информация и трассировка. Редактирование недоступно. На узком экране (≤768px) — единственный доступный режим. |
| **Редактирование** | Добавление/удаление объектов, прокладка кабелей, соединение волокон. Только для пользователей с правами редактора и ширины окна >768px. |

| Тип объекта | Назначение |
|-------------|------------|
| Узел сети | Конечное устройство на карте; в карточке — коммутаторы (RJ45 и SFP), медные линии к камере или медиаконвертеру; волокна ВОЛС с кросса («Подключить к узлу») |
| Оптический кросс | Соединение волокон (схема/таблица), медные порты, вывод волокон на узлы, ONU, сплиттеры, медиаконвертер и радиомост с маршрутом |
| Кабельная муфта | Сращивание волокон (схема/таблица), вывод волокон на ONU, сплиттеры, медиаконвертер и радиомост с маршрутом; установка на линию кабеля |
| Опора / крепление | Транзитные точки воздушной трассы |
| Колодец | Точка подземного участка: между соседними колодцами — всегда подземный пунктир |
| OLT (GPON) | Станция PON: приход от кросса, PON-порты, трассировка от порта (все пути при сплиттере) |
| Сплиттер | Делитель 1:N; входное волокно (с маршрутом) и выходы на ONU/сплиттер (с маршрутом через опоры) |
| ONU | Абонентский терминал; подключается волокном из кросса/муфты с маршрутом |
| Камера | Только медный кабель от коммутатора; зона обзора; в карточке — трассировка оптики к узлу |
| Медиаконвертер | Оптика с муфты/кросса, медь к коммутатору или камере |
| Wi‑Fi радиомост | Беспроводная связь P2P или P2MP; порт RJ45 (медь к коммутатору) или SFP (волокно с кросса/муфты); радиолинки и зона покрытия на карте |
| Коммутатор (отдельно на карте) | Точка с привязкой к родительскому узлу; медные и SFP-порты |
| Кабель | **ВОЛС** (волокна/модули в карточке); **медный** — от коммутатора к камере, МК, радиомосту и т.д.; опоры, крепления, колодцы — точки трассы |

**Добавление:** в режиме редактирования выберите тип в верхней панели и кликните по карте.

**Прокладка кабеля ВОЛС:** инструмент «Кабель» → точки трассы (муфта/кросс/OLT, опоры, крепления, колодцы). Типично: опоры → колодец → (клики) → колодец → опора → конец. **Медный кабель** — из карточки узла, коммутатора, медиаконвертера или радиомоста. **Радиолинк** — в карточке радиомоста: выберите второй мост / AP / станцию → «Подключить».

**Кросс / муфта:** рабочее место волокон (схема и таблица). Для свободного волокна — вывод на узел, ONU, сплиттер, кросс или радиомост. **Alt** + перетаскивание муфты — сдвиг вдоль трассы.

**Выделение областью:** ПКМ + протянуть — прямоугольник; статистика и «Удалить выделенное» в режиме редактирования.

В карточке объекта: **Удалить**, **Дублировать**, **Сохранить** (в рабочем месте кросса/муфты). При удалении опоры с кабелем — предупреждение.

## Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `Ctrl+Z` | Отменить последнее действие (до 20 шагов за сессию) |
| `Ctrl+Y` / `Ctrl+Shift+Z` | Повторить отменённое действие |
| `Escape` | Отмена текущей операции (размещение, кабель, волокно) |
| ПКМ + протянуть | Выделение области (в редактировании) |

## Синхронизация

- Сервер: `npm run api`. WebSocket: `/sync` на том же хосте (`ws://localhost:3000/sync` локально).
- При подключении клиент получает состояние карты своей организации; изменения передаются операциями.
- Список «В сети» и курсоры других участников на карте.
- Блокировка объекта на время редактирования карточки: один объект — один редактор.
- Инкрементальная синхронизация: правки уходят операциями по `uniqueId` с полем `revision`; при конфликте сервер отклоняет устаревшее изменение.
- Полная карта (`state`) — при импорте, undo/redo и массовых операциях; при открытой карточке или перетаскивании чужой full state откладывается.

Отдельный процесс только WS: `npm run sync`. Подробнее: [docs/SERVER.md](docs/SERVER.md#websocket-sync).

## Хранение данных

**На сервисе (volsmap.ru):** карты, пользователи, история и бэкапы на серверах; у каждой организации изолированный набор данных.

**Локально:** режим `storage: "json"` → `data/store.json` (`mapDataByOrg`, `historyByOrg`, `settingsByOrg`, `pricingPlans`); режим `storage: "mysql"` → MySQL 8+ (клиенту по-прежнему отдаётся собранный JSON карты). Один процесс `npm run api`.

- **Резервные копии:** `data/backups/<id_организации>/backup-YYYY-MM-DD.json`, 30 дней; для MySQL дополнительно `npm run backup:mysql`.

#### Работа с бэкапами

1. **Список** — в `data/backups/<id_организации>/` по одному файлу на день.
2. **Восстановление из приложения:** администратор организации → **Резервные копии** → дата → **Восстановить** → F5.
3. **Вручную:** остановить сервер → подставить данные из бэкапа в `store.json` для организации → запустить сервер.
4. **Экспорт карты** (Файлы → Экспорт) — ручная страховка.

## Настройка сервера

Шаблон: `server/config/server-config.example.json` → **`server-config.json` в корне проекта**.

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `port` | 3000 | Порт HTTP |
| `host` | `0.0.0.0` | Доступ по localhost и по IP в сети |
| `mapEngine` | `yandex` | `yandex` или `leaflet` (on-prem ортофото, см. [docs/ONPREM-BASEMAP.md](docs/ONPREM-BASEMAP.md)) |
| `yandexMapsApiKey` | — | Ключ API Яндекс.Карт (для `mapEngine: yandex`) |
| `publicSiteUrl` | — | Базовый URL сайта (например `https://volsmap.ru`) |
| `storage` | `json` | `json` или `mysql` |
| `mysql` | — | `{ host, port, user, password, database, connectionLimit }` |
| `freeMapObjectLimit` | 20000 | Лимит объектов на карте (облако) |
| `maxConcurrentUsers` | 4 | Одновременные пользователи организации |
| `authRateLimitWindowMs` | 900000 | Окно лимита входа (15 мин) |
| `authRateLimitMax` | 20 | Попыток с одного IP за окно |

Переменные окружения `PORT`, `HOST`, `STORAGE`, `MYSQL_*`, `AUTH_RATE_LIMIT_*` переопределяют поля конфига.

Полное описание: [server/config/README.md](server/config/README.md).

## Технологии

- Яндекс.Карты API 2.1 или Leaflet + локальные тайлы (`mapEngine`)
- Клиент: JavaScript без фреймворков, модули в `public/js/`
- CSS-переменные, светлая/тёмная тема
- Сервер: Node.js ≥ 20.9, Express, WebSocket (`ws`), хранилище JSON и/или MySQL (`mysql2`)
