# Карта оптической сети

Программа для работы с оптической сетью — веб-сервис для визуализации и учёта волоконно-оптической и смежной инфраструктуры на базе Яндекс.Карт: ВОЛС, узлы с коммутаторами, оптические кроссы и муфты, GPON (OLT, сплиттер, ONU), камеры и медиаконвертеры с медными линиями к коммутатору, Wi‑Fi радиомосты (P2P и P2MP) с радиолинками и зонами покрытия. Одна карта на организацию: данные изолированы по компаниям, хранятся на серверах, совместная работа через синхронизацию в реальном времени.

**Версия:** 1.2.0

**Работа в облаке:** [volsmap.ru](https://volsmap.ru/) — лендинг и вход; карта после авторизации. Установка ПО у заказчика не требуется.

**Документация:** каталог [docs/](docs/README.md) — структура репозитория, разработка, frontend, backend, справочник модулей в [public/js/README.md](public/js/README.md).

Ниже — краткий обзор; подробные инструкции для разработчиков — в `docs/`.

## Возможности

- **Визуализация** — узлы (в т.ч. с коммутаторами), отдельные коммутаторы на карте, оптические кроссы, кабельные муфты, опоры связи, крепления, кабели ВОЛС, объекты GPON (OLT, сплиттер, ONU), камеры, медиаконвертеры и Wi‑Fi радиомосты
- **Кросс и муфта** — рабочее место жил: вкладки «Схема» и «Таблица», соединения, вывод на узлы/ONU/сплиттеры/медиаконвертер/радиомост; у кросса — учёт медных портов (RJ45)
- **Медные линии** — подключение камеры, медиаконвертера или радиомоста к порту коммутатора узла или отдельного коммутатора; учёт портов RJ45 и SFP
- **Wi‑Fi радиомосты** — режимы P2P (точка‑точка) и P2MP (базовая станция и абонентские станции); порт RJ45 или SFP; прямые радиолинии на карте; зона покрытия (круг или направленный луч)
- **Трассировка жил** — путь оптического волокна от узла до узла через муфты и кроссы; от порта OLT (в т.ч. все пути при разветвлении через сплиттер); из карточки камеры — по жилам кросса, подключённым к узлу коммутатора (или по входной жиле медиаконвертера)
- **Редактирование** — добавление и удаление объектов, прокладка кабелей ВОЛС и медных линий, соединение жил в кроссах и муфтах, подключение жил кросса к узлам сети
- **Кабели** — ВОЛС 4/8/16/24 жилы: от муфты/кросса до муфты/кросса с опорами как промежуточными точками; медные — от коммутатора к камере, медиаконвертеру, радиомосту и др. по правилам карточки объекта
- **Кросс** — соединение жил между кабелями, вывод жил на узлы сети (выбор жилы и кнопка «Подключить к узлу»)
- **Группы** — объединение нескольких кроссов или узлов в одной точке
- **Регионы** — полигоны на карте, скрытие объектов внутри региона, сводка по содержимому
- **Поиск** — по названию в шапке, центрирование на объекте
- **Отмена и повтор** — до 20 действий за сессию: **Ctrl+Z** (отменить), **Ctrl+Y** (повторить); кнопки в шапке. Учитываются только ваши действия в текущей вкладке
- **Выделение областью** — зажмите правую кнопку мыши и потяните по карте; после отпускания панель со статистикой объектов и кнопка «Удалить выделенное» (в режиме редактирования)
- **Фильтр карты** — показ только выбранных типов (узлы, в т.ч. «только узлы агрегации», кроссы, муфты, опоры, крепление, OLT, сплиттеры, ONU, камеры, медиаконвертеры, Wi‑Fi радиомосты); кабели отображаются только между видимыми объектами
- **GPON** — OLT (приход от кросса, PON-порты, назначение жил), сплиттер (1:N, вход/выходы), ONU; подключение жилы к ONU и сплиттеру из кросса/муфты с прокладкой маршрута через опоры и крепления; выходы сплиттера на ONU/сплиттер с маршрутом; трассировка от порта OLT, в т.ч. все пути при сплиттере; экспорт/импорт полей GPON
- **Справочник устройств** — производители и модели для коммутаторов, OLT, ONU, камер, медиаконвертеров и Wi‑Fi радиомостов (вкладки в модальном окне администратора)
- **Экспорт / Импорт** — JSON карты организации
- **Авторизация** — администратор организации (редактирование) и пользователь (просмотр); глобальный администратор — панель `/site-admin.html`
- **Защита от ботов** — Cloudflare Turnstile на входе и регистрации; лимит попыток с IP
- **2FA для организации** — администратор организации включает общий TOTP-код (приложение-аутентификатор, например Яндекс.Ключ) для всех пользователей при входе
- **Организации и доступ** — отдельная карта, история и бэкапы на организацию; лимиты одновременных пользователей; личный кабинет с лимитами объектов на карте
- **История изменений** — журнал действий с фильтрами по пользователю, типу действия и датам; бейдж непрочитанных в шапке
- **Типы узлов** — обычный / агрегации с разными цветами и отображением внутри группы узлов
- **Начальная позиция карты** — каждый пользователь может сохранить текущий вид как начальный
- **Мобильный просмотр** — на экранах шириной ≤768px доступен только режим просмотра; редактирование — с компьютера или планшета в альбомной ориентации с большей шириной
- **Интерфейс** — складывающаяся левая панель; светлая и тёмная тема (интерфейс и подложка карты)
- **Синхронизация** — совместная работа в реальном времени (пооперационная), курсоры участников, блокировка объекта при редактировании карточки
- **Хранение** — `data/store.json`: организации, пользователи, карты по организациям (`mapDataByOrg`), история, настройки, карточки витрины (`pricingPlans`)
- **Резервные копии** — ежедневно для каждой организации в `data/backups/<id_организации>/backup-YYYY-MM-DD.json`; хранятся 30 дней

## Быстрый старт (пользователи сервиса)

1. Откройте [volsmap.ru](https://volsmap.ru/) и нажмите **Начать бесплатно** или **Войти**
2. Зарегистрируйте организацию или войдите под выданными учётными данными
3. В приложении откройте блок **Синхронизация** → **Подключиться** — загрузится карта вашей организации
4. На широком экране включите **Редактирование** для добавления объектов и кабелей

Данные хранятся на серверах сервиса; отдельная установка у вас не нужна.

## Локальная разработка

```bash
npm install
cp server/config/server-config.example.json server-config.json
# Укажите yandexMapsApiKey в server-config.json
npm run api
```

|-----|----------|

## Режимы и объекты

| Режим | Описание |
|-------|----------|
| **Просмотр** | Навигация, клик по объектам — информация и трассировка. Редактирование недоступно. На узком экране (≤768px) — единственный доступный режим. |
| **Редактирование** | Добавление/удаление объектов, прокладка кабелей, соединение жил. Только для пользователей с правами редактора и ширины окна >768px. |

| Тип объекта | Назначение |
|-------------|------------|
| Узел сети | Конечное устройство на карте; в карточке — коммутаторы (RJ45 и SFP), медные линии к камере или медиаконвертеру; жилы ВОЛС с кросса («Подключить к узлу») |
| Оптический кросс | Соединение жил (схема/таблица), медные порты, вывод жил на узлы, ONU, сплиттеры, медиаконвертер и радиомост с маршрутом |
| Кабельная муфта | Сращивание жил (схема/таблица), вывод жил на ONU, сплиттеры, медиаконвертер и радиомост с маршрутом |
| Опора связи | Транзитная точка (воздушные линии) |
| OLT (GPON) | Станция PON: приход от кросса, PON-порты, трассировка от порта (все пути при сплиттере) |
| Сплиттер | Делитель 1:N; входная жила (с маршрутом) и выходы на ONU/сплиттер (с маршрутом через опоры) |
| ONU | Абонентский терминал; подключается жилой из кросса/муфты с маршрутом |
| Камера | Только медный кабель от коммутатора; в карточке — трассировка оптики к узлу |
| Медиаконвертер | Оптика с муфты/кросса, медь к коммутатору или камере |
| Wi‑Fi радиомост | Беспроводная связь P2P или P2MP; порт RJ45 (медь к коммутатору) или SFP (жила с кросса/муфты); радиолинки и зона покрытия на карте |
| Коммутатор (отдельно на карте) | Точка с привязкой к родительскому узлу; медные и SFP-порты |
| Кабель | **ВОЛС** 4/8/16/24 жилы; **медный** — от коммутатора к камере, МК, радиомосту и т.д.; опоры и крепления — промежуточные точки для ВОЛС и медных линий |

**Добавление:** в режиме редактирования выберите тип в боковой панели и кликните по карте.

**Прокладка кабеля ВОЛС:** **Проложить кабель** → тип жил → начальная и конечная точка (муфта/кросс/OLT), при необходимости опоры и крепления. **Медный кабель** — из карточки узла, коммутатора, медиаконвертера или радиомоста. **Радиолинк** — в карточке радиомоста: выберите второй радиомост, AP или станцию и нажмите «Подключить» (линия на карте — напрямую между точками).

**Кросс / муфта:** карточка объекта открывает рабочее место жил (схема соединений и таблица). Для свободной жилы — «Подключить к узлу», к ONU, к сплиттеру, кросу или радиомосту.

**Выделение областью:** ПКМ + протянуть — прямоугольник; статистика и «Удалить выделенное» в режиме редактирования.

В карточке объекта: **Удалить**, **Дублировать**, **Сохранить** (в рабочем месте кросса/муфты). При удалении опоры с кабелем — предупреждение.

## Синхронизация

- Сервер: `npm run api`. WebSocket: `/sync` на том же хосте (`ws://localhost:3000/sync` локально).
- При подключении клиент получает состояние карты своей организации; изменения передаются операциями.
- Список «В сети» и курсоры других участников на карте.
- Блокировка объекта на время редактирования карточки: один объект — один редактор.
- Инкрементальная синхронизация: правки уходят операциями по `uniqueId` с полем `revision`; при конфликте сервер отклоняет устаревшее изменение.
- Полная карта (`state`) — при импорте, undo/redo и массовых операциях; при открытой карточке или перетаскивании чужой full state откладывается.

Отдельный процесс только WS: `npm run sync`. Подробнее: [docs/SERVER.md](docs/SERVER.md#websocket-sync).

## Хранение данных

**На сервисе (volsmap.ru):** карты, пользователи, история и бэкапы на серверах; у каждой организации изолированный набор данных.

**Локально:** `data/store.json` (`mapDataByOrg`, `historyByOrg`, `settingsByOrg`, `pricingPlans`). Один процесс `npm run api`.

- **Резервные копии:** `data/backups/<id_организации>/backup-YYYY-MM-DD.json`, 30 дней.

#### Работа с бэкапами

1. **Список** — в `data/backups/<id_организации>/` по одному файлу на день.
2. **Восстановление из приложения:** администратор организации → **Резервные копии** → дата → **Восстановить** → F5.
3. **Вручную:** остановить сервер → подставить данные из бэкапа в `store.json` для организации → запустить сервер.
4. **Экспорт карты** (Файлы → Экспорт) — ручная страховка.

## Настройка сервера

Шаблон: `server/config/server-config.example.json` → **`server-config.json` в корне проекта**.

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `port` | 3000 | Порт HTTP |
| `host` | `0.0.0.0` | Доступ по localhost и по IP в сети |
| `yandexMapsApiKey` | — | Ключ API Яндекс.Карт (обязателен для карты) |
| `publicSiteUrl` | — | Базовый URL сайта (например `https://volsmap.ru`) |
| `freeMapObjectLimit` | 2000 | Лимит объектов на карте |
| `maxConcurrentUsers` | 4 | Одновременные пользователи организации |
| `turnstileSiteKey` | — | Cloudflare Turnstile (клиент) |
| `turnstileSecretKey` | — | Turnstile (сервер) |
| `authRateLimitWindowMs` | 900000 | Окно лимита входа (15 мин) |
| `authRateLimitMax` | 20 | Попыток с одного IP за окно |

Переменные окружения `PORT`, `HOST`, `TURNSTILE_*`, `AUTH_RATE_LIMIT_*` переопределяют поля конфига.

Полное описание: [server/config/README.md](server/config/README.md).

## Технологии

- Яндекс.Карты API 2.1 (ключ с `/api/public-config`)
- Клиент: JavaScript без фреймворков, модули в `public/js/`
- CSS-переменные, тёмная подложка карты
- Сервер: Node.js, Express, WebSocket (`ws`), JSON-хранилище
